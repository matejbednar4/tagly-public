# Dev Fake Data Seed

Single-account dev seed, everything in **Prague**, built to exercise every
customer-facing share state. Run with `yarn seed` (verticals + notifications)
**then** `yarn seed:accounts` (this folder, `index.ts`).

Each file owns its own detailed plan in its docblock — this is the overview.

## Accounts

- **1 customer** — `matej@taglyapp.com` (matt, MALE, 900 followers, CZ/cs), referred
  by the advertiser. Has a standalone Prague-weighted IG snapshot (so reward
  estimates are healthy). → `customers.ts`
- **1 advertiser** — `matej@taglyapp.com` (entity null, CZ/cs, $2,000 deposit, no
  referrer). Available budget is reconciled down by the seeded shares. →
  `advertisers.ts`
- **1 admin** — `matej@taglyapp.com` (SUPER), seeded before shares so they can stamp
  `reviewedByAdminId`. → `admin.ts`

All three share the email `matej@taglyapp.com` but are separate accounts.

## Re-running

`index.ts` deletes all account data first (cascades handle queues, snapshots,
subsidization periods), so the seed is idempotent.
