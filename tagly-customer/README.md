# tagly-customer

Customer mobile app (iOS + Android). For patterns and coding conventions, see [CLAUDE.md](CLAUDE.md).

## Commands

```bash
yarn ios:dev      # iOS development build (do this first — triggers expo prebuild)
yarn android:dev  # Android development build
yarn start:dev    # Start Metro bundler (after device build succeeds)
yarn build:ios:staging
```

## Android Setup

### Prerequisites

- Android Studio with Android SDK and platform-tools installed
- `~/.zshrc` env vars:
  ```bash
  export ANDROID_HOME=$HOME/Library/Android/sdk
  export PATH=$PATH:$ANDROID_HOME/platform-tools
  export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"
  ```
- Physical device with USB Debugging enabled (or emulator running)
- Verify: `adb devices` should list your device

### First-time build

`android/` is generated by `expo prebuild`. `yarn android:dev` triggers it automatically if the folder is missing. If it's stale (e.g. after adding a new native plugin), delete and rebuild:

```bash
rm -rf android/
yarn android:dev
```

### Build speed (local dev)

Default builds target all 4 CPU architectures (~17 min). For local dev, restrict to your device's arch in `android/gradle.properties`:

```properties
reactNativeArchitectures=arm64-v8a   # covers most modern Android phones
org.gradle.jvmargs=-Xmx4096m -XX:MaxMetaspaceSize=512m
```

`expo prebuild` resets `gradle.properties` — re-apply after any prebuild. Never use single-arch for EAS/production builds.

### Firebase / Push Notifications

Android requires `google-services.json` for FCM. Without it the app runs but push notifications fail silently.

**API key cleanup (required every time you re-download from Firebase Console):** Firebase Console sometimes includes both a Firebase key and a Google Maps key. The Maps key causes `FIS_AUTH_ERROR` at runtime — `getExpoPushTokenAsync` hangs indefinitely. Each client's `api_key[0]` (the entry the google-services plugin uses) must be the Firebase key — identify it in GCP Console → APIs & Services → Credentials: the Firebase key's API restrictions include `fcmregistrations.googleapis.com` + `firebaseinstallations.googleapis.com`; the Maps key is restricted to `maps-android-backend.googleapis.com`. Safest is to strip the Maps key from every client (the production EAS var is stored stripped).

**Multi-environment setup:** two Firebase projects:
- `flaer-7f8bd` (stg-dev): `com.flaer.customer.dev`, `com.flaer.customer.staging` (+ advertiser twins)
- `flaer-prod`: `com.flaer.customer` (+ advertiser)

For local dev: download the combined stg-dev `google-services.json` → `tagly-customer/google-services.json` (gitignored). Canonical download: `npx firebase-tools apps:sdkconfig ANDROID <appId> --project <project>`.

For EAS builds, `GOOGLE_SERVICES_JSON` is a per-environment **file env var with `sensitive` visibility** (staging uses the `preview` environment, production uses `production`). `sensitive` — not `secret` — is required so the machine invoking `eas build` can pull the identical bytes for the fingerprint runtime version (see root CLAUDE.md gotcha "EAS fingerprint runtime version parity"). Two EAS quirks: a `secret` var cannot be changed to non-secret (delete it, then recreate), and non-secret file vars cap at 4 KiB — which is why the `preview` var holds a single-client file (just `com.flaer.customer.staging`) instead of the full stg-dev config:

```bash
eas env:delete preview --variable-name GOOGLE_SERVICES_JSON --non-interactive
eas env:create preview --name GOOGLE_SERVICES_JSON --type file \
  --value ./google-services.staging.json --visibility sensitive --non-interactive
```

Outside dev the env var is the ONLY source — `app.config.ts` has no filesystem fallback for staging/production, so nothing can silently pick up a stray local file. CI (`.github/scripts/eas-start-build.sh`) pulls the var and exports it before every Android build. To run a staging Android build from a laptop, do the same:

```bash
npx eas-cli env:pull preview --non-interactive
GOOGLE_SERVICES_JSON="$PWD/.eas/.env/GOOGLE_SERVICES_JSON" yarn build:android:staging
```

**Play App Signing SHA-1:** Google Play re-signs the AAB with its own certificate. For Maps to work on production Play Store installs, add Google's SHA-1 to the GCP Maps key restriction. Find it in: Play Console → App → Setup → App integrity → Play app signing → "App signing key certificate".

### AndroidManifest conflict

AppsFlyer SDK conflicts with `expo-secure-store` on `fullBackupContent`/`dataExtractionRules`. Handled via a `withAndroidManifest` config plugin in `app.config.ts` — no manual fix needed.
